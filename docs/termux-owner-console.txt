MarketFlow — لوحة إدارة مالك المنصة

التحديث بيضيف Owner console لحساب المالك فقط: متابعة الحسابات والحملات والمحتوى والاستراتيجيات، مراجعة السجلات، تعليق وصول العملاء أو إرجاعه، إنهاء جلساتهم، إعلان داخل المنصة، وإيقاف تغييرات الحملات والمحتوى مؤقتًا للصيانة. الحسابات العادية مش بتاخد صلاحية مالك تلقائيًا.

التركيب على تيرمكس:

1. أوقف الباكإند والواجهة بـCtrl+C في جلسة كل واحد.
2. نزّل marketflow-owner-update.pyz في مجلد Download، ثم نفّذ:

python /sdcard/Download/marketflow-owner-update.pyz

الأداة بتطبّق التحديث على فرع updates/owner-console-v1 وترفعه بدون force. بتحافظ على ملفاتك الخاصة وقاعدة البيانات الموجودة؛ لو فيه تعديلات متتبعة غير محفوظة أو عملية Git قديمة لم تنتهِ، هتتوقف بدل ما تمسحها. أول تشغيل للباكإند هيضيف أعمدة الصلاحية وحالة الحساب وجداول الإدارة بجانب البيانات الحالية.

3. بعد نجاح الرفع، افتح:

https://github.com/ahmedmsaad1347-ops/marketflow-app/compare/main...updates/owner-console-v1?expand=1

Create pull request → Merge pull request → Confirm merge.

بعد ظهور Merged:

cd ~/marketflow-app &&
git switch main &&
git pull --ff-only origin main

لو اتصال GitHub فشل وقت السحب، main المحلي لم يتحدّث. لو التثبيت نجح والفرع موجود بالفعل على جهازك، تقدر تشغّل النسخة الجديدة منه لحين رجوع الاتصال:

cd ~/marketflow-app &&
git switch updates/owner-console-v1

ما تستخدمش reset أو force، وما تنسخش قاعدة بيانات فوق الأصل. احتفظ بنسختك الأصلية وإعداداتك. لو احتجت نسخة احتياطية يدويًا، اقفل الباكإند الأول واحفظها في مكان خاص بعيدًا عن ملفات المشاركة وGit.

تشغيل النسخة الجديدة:

في جلسة الباكإند:

cd ~/marketflow-app &&
source .venv/bin/activate &&
python -m uvicorn backend.main:app --host 127.0.0.1 --port 3000

وفي جلسة ثانية للواجهة:

cd ~/marketflow-app &&
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort --force

افتح http://localhost:5173/app في نفس Chrome. سيب الجلستين شغّالين. مفيش مكتبات جديدة مطلوبة للتحديث ده. فقط لو ظهر خطأ مكتبة ناقصة زي httpx، ثبّت متطلبات المشروع داخل نفس .venv ثم أعد تشغيل الباكإند:

cd ~/marketflow-app &&
source .venv/bin/activate &&
python -m pip install -r requirements.txt

تفعيل حسابك كمالك — مرة واحدة:

لازم الباكإند الجديد يكون بدأ مرة عشان يجهّز أعمدة الصلاحيات. استخدم حسابك الموجود بالفعل، المفعّل بالبريد، واللي تقدر تدخل له بكلمة السر الحالية. مش محتاج حساب بديل أو كلمة سر جديدة للإدارة.

في جلسة تيرمكس ثالثة:

cd ~/marketflow-app &&
source .venv/bin/activate &&
python tools/setup_owner.py --email "ahmedmsaad1347@gmail.com"

الأداة هتعرض مكان قاعدة البيانات، وبعدين تطلب Current account password. اكتب كلمة السر الحالية واضغط Enter؛ الحروف مش هتظهر أثناء الكتابة. ما تكتبش الباسورد داخل الأمر أو تبعته في صورة.

لو حسابك المفعّل بإيميل مختلف، استخدم الإيميل الفعلي مكان المثال. الأمر لا ينشئ حسابًا ولا يتخطّى التفعيل. لو فيه مالك تاني متسجل، مش هينقل الصلاحيات لحساب جديد. تكراره لنفس حساب المالك بالبيانات الصحيحة لا يضيف مالكًا آخر.

بعد النجاح الجلسات القديمة لحسابك هتتقفل، فارجع إلى http://localhost:5173/app وسجّل الدخول من جديد. من القائمة الجانبية، أو قائمة الموبايل، افتح Owner console. الحسابات العادية مش هتشوف مدخل لوحة المالك، والـAPI نفسه بيمنع وصولها حتى لو حاولت تفتح الصفحة مباشرة.

تثبيت المصدر بيحافظ على البيانات. تفعيل المالك خطوة مقصودة بتضيف الصلاحية لحسابك وتسجل العملية وتنهي جلساته القديمة؛ لا تبدّل قاعدة البيانات ولا ترجعها لنسخة قديمة.

لو الحساب لم يُفعّل بعد:

كمّل إنشاء/تفعيل حسابك العادي من Chrome الأول. في وضع الرسائل المحلي، رابط التأكيد بيتحفظ على جهازك ومش بيتبعت لجيميل. لعرض آخر رابط خاص ببريدك من جلسة الأوامر:

cd ~/marketflow-app &&
source .venv/bin/activate &&
python tools/open_auth_email.py --purpose verify --email "ahmedmsaad1347@gmail.com"

انسخ الرابط كاملًا وافتحه في تبويب عادي في نفس Chrome، وكمّل التأكيد. لا تبعت الرابط أو التوكن أو كلمة السر هنا. لو الأمر مش لاقي رسالة، نراجع البريد وملف البيانات بدل ما نمسح القاعدة أو نكرّر حسابات جديدة.

تجربة سريعة بعد فتح Owner console:

- Overview: راجع أعداد الحسابات والحملات والمحتوى، وحالة قاعدة البيانات والبريد. الأعداد جاية من البيانات الفعلية. Active sessions معناها جلسات لم تنتهِ، مش عدد أشخاص أونلاين.
- Users: ابحث عن حساب عميل تجريبي تملكه، مثل حساب بتستخدمه لاختبار المنصة. ما تختبرش تعليق الوصول على عميل حقيقي. افتح Manage وراجع بياناته وأعماله.
- لو عندك حساب اختبار منفصل، جرّب Suspend access مع سبب مثل «اختبار إيقاف وصول حساب تجريبي» وكلمة سر المالك، ثم Restore access لإرجاعه. أعمال الحساب تفضل موجودة، وبعد الإرجاع يسجّل الدخول من جديد. حساب المالك محمي من التعليق بهذه الأزرار.
- Campaigns: افتح حملة تجريبية مثل «مزاج — طلبات قهوة جديدة». جرّب Archive campaign ثم Return to draft، وتأكد إن نص الحملة والميزانية لسه موجودين. الحالات دي داخل مساحة العمل؛ مش بتشغّل أو توقف إعلان حقيقي.
- Content: افتح مشروعًا محفوظًا وراجع الإصدارات. لو الإصدارات أكتر من20، استخدم الصفحات للوصول للباقي.
- Activity: هتلاقي مراجعات الحسابات والسجلات والتغييرات الإدارية مسجلة بالوقت والفاعل. اكتب أسبابًا إدارية واضحة من غير أسرار أو كلمات مرور.
- Settings: جرّب إعلانًا نصيًا مثل «تحديث تجريبي للمنصة، شكرًا لتجربتكم». الحفظ يطلب كلمة سر المالك والسبب.
- جرّب Pause customer workspace changes فقط لو فيه حساب اختبار جاهز. الحساب العادي يفضل يقرأ ويسجّل الدخول ويسترجع الباسورد، لكن تغييرات الحملات والاستراتيجيات والكرياتيف تتوقف. الإدارة تفضل متاحة. ألغِ الوقف بعد الاختبار وامسح الإعلان التجريبي.

حدود مهمة لفهم الأرقام:

سجل أخطاء الطلبات يبدأ من هذا التحديث؛ يحتفظ بآخر1000 خطأ API بحالة400 أو أعلى ويعرض أحدث15 في النظرة العامة. تسجيل الدخول والحسابات مستبعدة، ولا تُحفظ أجسام الطلبات أو روابط الاسترجاع أو كلمات المرور. مفيش سجل أخطاء تاريخي قبل تفعيل التحديث.

البريد المحلي يظل محليًا حتى إعداد SMTP. ظهور Google/Facebook/AI على إنه Configured معناه وجود إعدادات، وليس تأكيد نجاح خدمة خارجية. مدة التشغيل تخص عملية السيرفر الحالية، وحجم قاعدة البيانات لا يشمل ملفات journal. مفيش قياس اشتراكات أو فواتير أو أرباح المنصة أو تكلفة موديل مدفوع أو مراقبة إنتاج شاملة.

اللوحة ومحرك الكتابة والتخطيط المحليين لا يحتاجوا مفتاح AI مدفوع. التحديث لا يضيف MFA ولا يغني عن HTTPS وضبط الاستضافة عند النشر الحقيقي، ولا يفعّل إرسال البريد أو منصات الإعلانات تلقائيًا.

الاختبارات الأمنية وتجارب المتصفح وإعادة تثبيت الحزمة تُسجّل نتيجتها الفعلية مع ملفات الإصدار. لو ظهر خطأ، توقف عنده وابعت نصه فقط من غير أسرار. لا تمسح الحسابات أو .env أو قاعدة البيانات عشان تحل مشكلة صلاحية المالك.

التحقق قبل تجهيز الإصدار:136 اختبار وحدة/API نجحوا، منهم17 اختبار لصلاحيات الإدارة والتفعيل والإيقاف والحماية. بناء الإنتاج وتجربة متصفح مع باكإند فعلي نجحوا، بما فيها الموبايل والثيمات وسجل21 إصدار. التجارب استخدمت حسابات وبيانات تجريبية منفصلة؛ تفعيل حسابك الحقيقي كمالك يحصل عندك بالخطوة المذكورة بعد تثبيت النسخة الجديدة.
